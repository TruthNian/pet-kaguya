2026-10-08。基准是 `baseline-phase2-complete-20261008`，候选是 `pet/`。数据来自同一套 `tools/audit.py`，旧审计与此处 alpha 阈值不同，不混用数值。

## 当前修正（必须先读）

用户现已选择完整 AI 生成母版 canonical-v3 并锁定脸型；程序修脸因发丝弯折失败而停止，不再回用。原始输出、选择理由和哈希在 `sources/canonical/manifest.json`。此决定只解决制作源的选择；现有九状态候选及16视线已组成完整覆盖开发验收图集，仍不能把待视觉接受、状态切换或性能问题标成已修复/可安装。

左右小步是保持正面的方案原型，策略尚未获确认。源腿/兔鞋独立运动、支撑脚坐标固定、原脸与饰品侧别保留，但没有完整重心转移；80px提示弱、估计轮廓可能带发丝/残影，中立拆层并非无损。实际宿主的左右跑是拖拽反馈：鼠标位移独立于固定时钟，没有速度参数；松手可中断任意格并恢复底层任务状态，不一定idle。因此“屏幕世界无脚滑”“松手总在三轮后回idle”均不能宣称成立。R10保留未达边界，不用格内接触检查代替。

waiting 六格保持托腮（1010 ms×3）、review 六格低手下视（1030 ms×3）已制作，仅有微小耳发响应，不强行做快速呼吸/反复抬放。手势策略与视觉接受均待确认，不能写成共识。review 的右掌更展开、袖褶偏硬，恢复前景只是原像素片而非干净层；80 px 的手势/下视提示很弱。入场/回 idle 放手过渡仍缺，循环首末像素相同不抵消跨状态跳变。完整开发覆盖已有，不是完成的全局验收或正式图集发布安装；详见 `PHASE5-STATES.zh-CN.md`。

processing 的新候选保持原眼开口、向手边移原虹膜、胸腰旁收手，没有半闭眼、胸饰闪色或快速身体脉冲。四张姿势占六个真实停留格、820 ms×3 后回 idle；80 px 手势/视线很弱，回 idle 的放手过渡仍缺，不宣称“困倦/状态表达/身体冻结全部修复”。详见 `PHASE5-STATES.zh-CN.md` 的否定证据与当前限制。

review 旧袖背后的发丝接缝仍未修复。最新两个无脸局部生成/合成实验未采用：首次画回旧手袖；第二次内部线条稍清楚，但与原发束仍错接，有界羽化或RGB边界求解均不足。两种实验均能保持父alpha和衣服/手/脸不变，却不构成审美通过证据；当前动作条及全局图集保持v2，详见最新局部对照及失败记录。

完整范围见 `REQUIREMENTS.zh-CN.md`。下面表格记录 Phase 3 发布时判断，部分结论已被实际视觉证据推翻，不代表现在通过：failed 供体皮肤/下颌拼接有错，waiting 继承旧拼接；“每帧不同”和“alpha 不同”不证明自然。Phase 4 静态头部拼接试作又被用户否决，不能作为动画基础，详情见 `STATIC-REVIEW.zh-CN.md`。安装目录未被本轮更换。

## 本轮新发现并修正的问题

1. 发梢位移场原本误带到鞋边，锚点测试失败；加入鞋部排除区域后各静立/方向鞋部像素固定。
2. 初版跑腿局部压缩过强，Jacobian 下限仅约 0.10；扩大过渡区、收敛角度后 64 个相位采样最小值约 0.53，测试要求大于 0.50。
3. 初版轻跃按错误的时间分母布点；改为从 840 ms 实际周期自动推导，最后长帧明确落地。
4. 第一笔 GitHub 提交因复制路径错误缺图集；完整基准在第二提交和 `baseline-phase2-complete-20261008` 中，旧历史不隐藏。
5. 安装器隔离测试发现 PowerShell 把 File.Replace 的 null 备份参数转为空路径；改为显式备份文件后重新验证。未在真实安装目录试错。

## 诚实的结论与下一轮优先级

现在比冻结/重画混杂的基准更一致、更克制，但不能称“所有问题彻底解决”，尤其不能称原生高分辨率、高帧率或真实立体骨骼动画。

下一轮值得解决的是完整步态关键姿势、跨状态共用的分层母版以及真人实际使用反馈。先判断这些在小尺寸下是否真的有收益，再考虑重绘。更高帧率、短眨眼、方向迟滞和任务状态保持需要宿主能力；在用户已确认的本轮边界内保留问题，不修改签名应用、不绕过限制。
