# 原像素手袖运动与 GIMP 工程

这次不是新增一张宠物母版，也没有采用新招手策略。已锁定的 v3、现用 waving 行、全局开发图集和本机安装文件保持不变。`wave-source-rig-v1/v2` 都是未采用实验；v2 只更换隐藏头发底图，没有重新生成前景手袖。角色身份保持只是必要条件，不等于动作自然。

## 从已知条件推导

母版只记录被遮挡后的颜色，没有袖后头发，也没有画师前景透明层。`S = P + (1-β)B` 每个像素只有三个颜色观测，却至少含四个前景未知量；背景 B 也需估计。即使零位移精确还原 S，仍可能把头发或旧描边分到错误层，运动时才出现残影。因此非负材料色、零位移等式和实际移动后的轮廓必须分别检查。

v1 使用此前底图，v2 通过内置 imagegen 对无脸512×512裁切进行“仅移除左手袖、补隐藏金发”编辑。[输入](../candidates/phase5/source-arm-backing-v2/input.png)、[实际提示词](../candidates/phase5/source-arm-backing-v2/prompt.txt)、[原始生成](../candidates/phase5/source-arm-backing-v2/generated.png)单独归档。1254×1254输出按原裁切坐标统一比例投影，不按物体边界拟合；整张裁片不采用。仅在估计旧手袖区域读取底色，已知外部恢复母版，原alpha整面保留。它仍不是可靠恢复了所有隐藏发束。

动作假设是估计肘点(449,703)、腕点(356,743)驱动低位小动作；手掌刚性转动，下垂长袖逐渐跟随腕位移，上肩保持。袖口上缘落在衔接区，因此**撤回“整个袖口与手掌刚性共转”判断**。没有完成肘腕骨骼，也没有证明这足以表达招手。

## 五步法的实际取舍

1. 质疑：四格不要求独立重画，也不要求每格独一无二；固定宿主停留不能借假补间绕过。
2. 删除：不用新脸、新手和新衣纹替换母版，不把蒙版合法性当视觉接受，不替换现用行。
3. 简化：一份原手袖、一个隐藏底图、固定相机、四个受限变形角度，先暴露轮廓问题。
4. 优化：高度淡出曾把材料局部面积压至约0.825；改成极角衔接后，70px袖面过渡仍约0.885。扩大至170px后当前正/负运动全区最小Jacobian约0.910/0.925；逆映射检查阈值1e−5源像素。这只限制变形，不证明解剖或衣褶正确。
5. 自动化：原alpha/受保护像素不变、同材料零位移、掌内刚性/腕长、实际四格停留、未知层声明和GIMP保存/重开证据。工程检查不替代观看。

## 真实编辑器成果与否定结果

[GIMP XCF](../sources/editor/source-arm/kaguya-source-arm.xcf)含5层、2蒙版：估计隐藏底图、可编辑原手袖蒙版、锁定母版参考、未通过的+6°诊断图和保护指南。由GIMP 3.2.6真实保存、重开、导出，重开前后导出RGBA一致；可见像素精确等于母版，859处完全透明隐藏RGB归零。使用浮点非线性RGB正常叠加与底层补偿；修改蒙版后须重算补偿，不能把工程称为原画师干净层或可直接拖动的完整rig。没有声明桌面手绘，CI只验证归档/导出，不运行GIMP。

旧稀疏轮廓漏掉指尖/下摆描边，深色阈值又漏掉棕色抗锯齿；失败分别保留在v1。修正后，新底图减少部分旧轮廓，但**运动帧仍存在下摆残影和局部发丝明暗接缝**，不能采用。新材料不是“问题已解决”的证据。

四格是0°/+6°/−3°/0°，140/140/140/280ms。[GIF](../candidates/phase5/wave-source-rig-v2/native-timing.gif)为调色板QA无限循环，不模拟宿主700ms×3后回idle。80px动作弱、招手策略未获确认、任意状态切换仍有跳变；没有提高宿主帧率、分辨率或实测CPU/GPU性能。下一步应修真正的前景边界和背景连续性，再审查非零姿势；不先扩大运动或发布安装。
