# 原像素手袖运动与 GIMP 工程

这次不是新增一张宠物母版，也没有采用新招手策略。已锁定的 v3、现用 waving 行、全局开发图集和本机安装文件保持不变。`wave-source-rig-v1/v2/v3` 都是未采用实验；v2更换隐藏头发底图，v3修正原袖边选区和背景约束，都没有重新生成前景手袖。角色身份保持只是必要条件，不等于动作自然。

## 从已知条件推导

母版只记录被遮挡后的颜色，没有袖后头发，也没有画师前景透明层。`S = P + (1-β)B` 每个像素只有三个颜色观测，却至少含四个前景未知量；背景 B 也需估计。即使零位移精确还原 S，仍可能把头发或旧描边分到错误层，运动时才出现残影。因此非负材料色、零位移等式和实际移动后的轮廓必须分别检查。

v1 使用此前底图，v2 通过内置 imagegen 对无脸512×512裁切进行“仅移除左手袖、补隐藏金发”编辑。[输入](../candidates/phase5/source-arm-backing-v2/input.png)、[实际提示词](../candidates/phase5/source-arm-backing-v2/prompt.txt)、[原始生成](../candidates/phase5/source-arm-backing-v2/generated.png)单独归档。1254×1254输出按原裁切坐标统一比例投影，不按物体边界拟合；整张裁片不采用。仅在估计旧手袖区域读取底色，已知外部恢复母版，原alpha整面保留。它仍不是可靠恢复了所有隐藏发束。

动作假设是估计肘点(449,703)、腕点(356,743)驱动低位小动作；手掌刚性转动，下垂长袖逐渐跟随腕位移，上肩保持。袖口上缘落在衔接区，因此**撤回“整个袖口与手掌刚性共转”判断**。没有完成肘腕骨骼，也没有证明这足以表达招手。

## 五步法的实际取舍

1. 质疑：四格不要求独立重画，也不要求每格独一无二；固定宿主停留不能借假补间绕过。
2. 删除：不用新脸、新手和新衣纹替换母版，不把蒙版合法性当视觉接受，不替换现用行。
3. 简化：一份原手袖、一个隐藏底图、固定相机、四个受限变形角度，先暴露轮廓问题。
4. 优化：高度淡出曾把材料局部面积压至约0.825；改成极角衔接后，70px袖面过渡仍约0.885。扩大至170px后当前正/负运动全区最小Jacobian约0.910/0.925；逆映射检查阈值1e−5源像素。这只限制变形，不证明解剖或衣褶正确。
5. 自动化：原alpha/受保护像素不变、同材料零位移、掌内刚性/腕长、实际四格停留、未知层声明和GIMP保存/重开证据。工程检查不替代观看。

## 真实编辑器成果与否定结果

[GIMP XCF](../sources/editor/source-arm/kaguya-source-arm.xcf)含5层、2蒙版：估计隐藏底图、可编辑原手袖蒙版、锁定母版参考、未通过的+6°诊断图和保护指南。由GIMP 3.2.6真实保存、重开、导出，重开前后导出RGBA一致；可见像素精确等于母版，859处完全透明隐藏RGB归零。使用浮点非线性RGB正常叠加与底层补偿；修改蒙版后须重算补偿，不能把工程称为原画师干净层或可直接拖动的完整rig。没有声明桌面手绘，CI只验证归档/导出，不运行GIMP。

旧稀疏轮廓漏掉指尖/下摆描边，深色阈值又漏掉棕色抗锯齿；失败分别保留在v1。修正后，新底图减少部分旧轮廓，但**运动帧仍存在下摆残影和局部发丝明暗接缝**，不能采用。新材料不是“问题已解决”的证据。

四格是0°/+6°/−3°/0°，140/140/140/280ms。[GIF](../candidates/phase5/wave-source-rig-v2/native-timing.gif)为调色板QA无限循环，不模拟宿主700ms×3后回idle。80px动作弱、招手策略未获确认、任意状态切换仍有跳变；没有提高宿主帧率、分辨率或实测CPU/GPU性能。下一步应修真正的前景边界和背景连续性，再审查非零姿势；不先扩大运动或发布安装。

上轮提交edc8401的[CI](https://github.com/TruthNian/pet-kaguya/actions/runs/37886464223)成功：148项Python、26项Node、隔离安装器、471件逻辑重建一致。373件图片编码字节不同，但解码像素/时序/JSON/浮点材料一致。此前本地首轮重建因运行期间补录JSON字段而失败；冻结文件后重跑通过，不用失败轮替代通过证据。本轮v3须独立全量重建和新提交CI，不能继承旧绿灯。

## v3：修正的具体错误与剩余边界

之前“已完整选到袖边”的判断不成立。稀疏多边形搜索范围漏选13个相邻绿色原袖像素，例如源坐标(427,903)、(426,905)、(425,908)、(423,913)、(422,915)；它们被错误当作可见背景，运动后留在原位。v3在同一权限/保护区内跟随实际连通绿色袖面及邻接描边，增加221个原材料像素，不扩大改脸、另一侧身体或鞋的权限。不是靠调颜色藏掉旧袖边。

底图只在会移动的估计前景下求解；固定根部不作为头发观测。约束来自蒙版外、未受保护、alpha至少240且非绿色衣料的源像素。**“可见头发”选择仍是估计**，不能称为画师语义真值。首轮1202条观测邻接约束的梯度引导求解，随后利用两个真实外部样本，对平缓边缘推断771个向内样本；这些样本不是源图已知像素，也不保证所有发束走向或一阶连续。首/次求解分别裁切534/737个RGB通道，推断处另有8个通道裁切，因此不能声称完全保持全部指导梯度。

[非零姿势对照](../candidates/phase5/wave-source-rig-v3/detail.png)可见手旁块状拼接和旧绿色袖边减轻；下摆浅弧、细发丝连续性仍未解决。中性由同一材料还原母版，非零变化仅限权限内；这两项测试不证明衣袖结构或自然度通过。上袖口仍不全刚性，低位动作在80px尤其弱，完整抬手/放手和任意状态切换仍缺。

本地新工程`work/gimp-source-arm-refined-v3/kaguya-source-arm.xcf`由GIMP 3.2.6保存/重开，有5层和2蒙版；两次导出RGBA一致，可见像素精确等于母版，859处完全透明隐藏RGB归零。它只在本地work中，**公开XCF链接仍是上轮v2材料**，不冒充新归档。首次创建因候选缺少保护蒙版失败，补全可重建蒙版后重跑成功。`tools/gimp_source_arm_project.py`可指定`MATERIAL_INPUT`和新`PROJECT_OUTPUT`，拒绝覆盖现有XCF；原始估计材料/补偿限制不变，不声明桌面画笔修图或干净rig。

验收页菜单新增招手行的原像素实验别名，不是第十个原生状态；实际140/140/140/280ms、三轮后回idle，支持单帧、暂停和减少动态。独立页实查四格、80/113/224px、三轮回退、暂停绘制计数不变，未见控制台warning/error。它没有替换现用wave、全局或安装文件；27项Node时钟测试通过，完整视觉接受仍pending。页面截图不是宿主性能或自然度证明。

本轮本地全量156项Python通过（206.824s），随后修正空求解域诊断字段并复跑5项求解器测试通过；27项Node通过。冻结候选后严格重建497件逻辑内容，解码像素/时序/JSON/f32全部一致，本机编码字节差异0。选定母版与已安装文件SHA、现用全局图集解码RGBA均未改变。这是本地证据，新提交的CI仍须独立核对。
