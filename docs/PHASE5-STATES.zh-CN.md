# Phase 5：同一母版的动作与缺画素材

## 新增：waiting 保持托腮、review 低手下视候选

两者各有六个真实时间槽、四张实际 cel、首末 RGBA 相同：waiting 第 6 行 `[150,150,150,150,150,260]` ms，1010 ms×3＝3030 ms；review 第 8 行 `[150,150,150,150,150,280]` ms，1030 ms×3＝3090 ms，然后回 idle。没有改变原生帧数、停留、分辨率或补间能力。保持托腮与双手低处轻合的选择问题尚无回复，`strategyUserApproval` 与视觉状态均保留 pending，不把制作候选当作共识。

第一性原理从物理和信息边界出发：同一角色的头脸、取景和身份不应随任务改变；托腮手必须相对脸保持接触；合手要有两条实际连回肩肘的手袖及明确前后遮挡，不能靠整张新画解决。宿主只重复同一行三遍，因而一个行条不能同时编码“仅第一遍抬手、仅第三遍放手”。这一秒左右周期也不是适宜的悠缓呼吸周期。状态有区别是目标，但每状态必须加道具、每格必须不同、每轮必须呼吸并不是必要条件。

五步法实际执行：质疑上述假要求；删除整张新脸、书本道具、胸饰闪烁、快速身体脉冲和伪过渡；简化为保持手势与原眼内视线、微小耳发响应；先检查真实连接及 80–224 px 后再加时钟，复用已求出的比较帧，不为四个尺寸重复完整求值；最后自动化局部权限、源像素、接触坐标、原眼 alpha、真实停留、行透明格和精确重建。微动存在不是自然度证明，也不能用绘制次数、像素差或测试数量抵消画面缺陷。

waiting 复用已画的 v3 局部托腮，身体/脸/手接触坐标保持，耳尖不超过 0.15°、发梢 0.02°，不做一秒一次抬放或闭眼。首格与此前静态原生帧完整 RGBA 相同。新增源图权限守卫拒绝把托腮前景扩到眼睛，拒绝手臂补片超过显式预算；即使非法区域恰好没有实际改色也拒绝。`waiting-art-v1/` 仍是静态关键姿势材料，`waiting/` 才是六格行条。

review 在 processing 的局部左手姿势上补缺失右手/衣袖和旧袖后的背景。内置 `image_gen` 的实际提示词、引导、参考与原始结果归档于 `review-art-v1/`；输入是无脸的固定 520×510 裁片。实际生成 1266×1242 不是严格同尺寸输出，以同一宽度比例投影回源矩形，约 0.1422 源像素的超高裁去，不按物体轮廓拟合。右臂有界组合改变 69679 像素、区域外 0；整张映射裁片在采用边界外改变 189432 像素，未整片采用。恢复原左手、小肩披、前发和红绳前景像素；眼外原头脸不变。动画仅平移原虹膜源图 `[0,5]` px，原眼开口、脸形与 alpha 固定，身体保持、耳发范围与 waiting 相同。新左右手材料各有先行裁片投影，不能写成全流程只重采样一次。

具体不足仍存在：

- review 右掌更展开，旧左手更蜷，手体积/轻合关系尚未通过视觉认可；生成袖褶偏硬、展开体积较大，不能称提示词完全实现。
- 恢复的前景是有界原像素片，不是干净的原作者 RGBA 层。边缘可能夹带原背景；月饰部分被新手合法遮挡，没有重新画一个月饰补上。遮挡与衣褶仍需审查。
- waiting/review 身体保持不动，只做轻微耳发响应，不宣称原先所有身体冻结问题已解决。80 px 下合手与下视的辨识非常弱；224 px 可见并不证明所有尺寸清楚。
- 两个保持手势的行条都没有入场和回 idle 放手过渡；循环接缝相同只解决行内重播，不解决跨状态跳变。未用交叉淡化、重复快速抬放或假宿主改动掩盖。
- 没有完整手臂 rig、侧身步态、全局九状态接受或新安装包。

## 新增：清醒专注的 processing 候选

`processing/` 对应宿主内部 `running` 第 7 行，不是左右跑。真实停留 `[120,120,120,120,120,220]` ms，820 ms 一轮、三轮 2460 ms 后回 idle。六个时间槽使用四张实际姿势，首两格复用、首末完整 RGBA 相同。没有强制每格独立画图、快放、补间或原生帧率升级。

从必要条件推导：处理中应清醒、和托腮 waiting 区分，但不需要“忙碌就必须摇动身体”。宿主 820 ms 的重复周期不适合一轮一次悠缓呼吸；将其强行改成呼吸会得到约每秒一次的快速身体起伏。因此删去半闭眼、胸饰闪色和快速身体脉冲，简化为胸腰旁轻收手、原虹膜向手边平移源图 `[-6,3.5]` px，以及不超过 0.20° 的耳尖、0.02° 的发梢响应。身体保持不动；**并未据此宣称身体冻结的全部问题都已解决**。注视偏移只是现有眼层能力的一半，不改眼眶、嘴、眉、下颌或脸 alpha。

缺画只补左手/长袖，内置 `image_gen` 实际提示词及原始结果归档于 `processing-art-v1/`。使用不含脸的固定 300×500 裁片，生成 971×1619 输出以同一个横纵比率投影回源矩形，裁去约 0.206 源像素的超高部分；不按物体轮廓拟合，不独立缩放头身。再使用共同隐藏底图、恢复原肩披/前发，只采纳手袖多边形。局部姿势改变 64291 源像素，补片外改变 0；原始裁片在补片外改变 83869 像素，未整片采用。新手插片已有一次先行重采样，随后才共用相机、3×覆盖取样和末端下采样，不能声称所有素材总共只采样一次。

五步法：质疑“处理中必须每格动/做呼吸”的假要求；删除半闭眼、胸饰特效、整张新脸与快速脉冲；简化成同一身体上一个有界手势和原眼层；先看固定坐标下的手腕/衣褶及 80–224 px，再检查真实时钟、遮挡和源像素；最后自动化保护与精确重建。不把“六帧哈希不同”当动画价值，也不把四个不同 cel 当足够自然。

本轮否定证据：

- 生成手更像柔和握拢，而非提示词要求的松散微捧，不能称严格遵循提示。布料体积、手袖连接仍需人工接受。
- 80 px 下手势与视线提示非常弱；224 px 可见收手，不等于小尺寸状态已清楚可辨。
- 每轮均保持收手，末格不是原始放松手。图集不能同时编码“仅第一轮收手、仅第三轮放手”；2460 ms 回 idle 的手部跳变仍未解决。没有用重复短周期抬放或交叉淡化掩盖。
- 新负例先发现：只检查“实际像素有无改变”会放过包含脸的非法补片权限，因为本次裁片的脸区恰好仍是源图。已新增权限区域与受保护矩形相交即拒绝，不依赖实际改色。
- 0.22° 耳响应的采样 Jacobian 最小约 0.949766，未达到既定 >0.95 门槛；改为 0.20° 后重新验证，没有放宽门槛。这是局部面积变化守卫，不是美感评分。
- 首版 GIF 测试用最相似 RGB 帧推断姿势，微小动作比调色板量化误差更接近，误匹配。已改为独立逐格调色板量化、合并相邻相同显示，再精确比较时间加权像素哈希与停留；GIF 仍只是调色板 QA，不替代 RGBA 条。

## 新增：四个真实时间槽的招手候选

`waving/` 为低位过渡、肩旁招呼、重复同一过渡、原始放松姿势，真实停留 `[140,140,140,280]` ms；700 ms 一轮、三轮 2100 ms 后回 idle。三张实际姿势占四格，复用下降姿势不是缺帧，也不强求无意义的四张独立图。末格与 v3/idle 第 0 格完整 RGBA 相同，最后 280 ms 占一轮 40%，不会在招呼最高点长停。但三轮抬放与离散跳变仍需判断，时间正确不等于优雅自然。

第一性原理约束：举手会露出旧袖后的头发，手腕必须连到同一肩肘，原脸/饰品/鞋不能跟着重画。先使用已有有界隐藏底图，再只取新手/袖，最后把原小肩披和前发恢复到前景。原图尺度与相机固定；边界外源像素逐个保持。新画不是可验证的原作者分层，也不是完整手臂 rig。放松格是明确采用原图，不是“抽出前景再重建中性”的证明。

五步法具体执行：质疑四格是否必须四张不同图；删除独立整脸重画、全身摆动与伪补间；简化到共用身体/底图和两个局部画帧；先反复检查实际手高、袖口及 80/224 px，再自动化源保护、遮挡、保存像素、实际停留及回退。不能用这些工程约束自动批准手形、衣褶或可爱感。

否定证据原样保留：第一张 `wave-art-v1` 手升到脸旁，没有按低位要求制作，排除；`wave-art-v2` 手降到肩旁，但指尖约 y=560，而不是引导 y=600，仍不算准确遵循引导。整张输出在当前采用边界外改变 762849 像素，未整张采用。第一张中间姿势 `wave-art-middle-v1` 手仍在峰值高度，仅改袖长，排除。随后使用不含脸的固定裁片编辑，中间手实际下移并朝放松方向转，但更靠近放松位置，**不是等距半抬姿势**。生成的 971×1619 裁片以相同横纵缩放投影到固定 300×500 源矩形，多出的约 0.206 源像素高度裁去；没有按物体轮廓重新拟合，原脸/主体无变化。这个新画插片有一次先行重采样，不能隐去而笼统说全素材只采样一次。

取样范围初版碰到受保护肩披，被构建拒绝；收回到肩披下方后，目视又发现红上袖被截断，已沿真实外轮廓修正。峰值/过渡分别改变 66870/63557 源像素，区域外均 0。像素计数不是美感评分；袖褶、手掌体积、隐藏头发接缝和四格节奏人工接受均 pending。两张输入不是“新的更好整人”，只是旧母版缺少的局部画帧。

## 新增：十六方向仅眼内视线候选

`look/` 已制作 16 格，0 为上、顺时针每 22.5°，按原生第 9/10 行映射。只平移原虹膜材料；固定眼开口、睫毛、眉、嘴、下颌、身体、月饰及鞋，不全身旋转、不镜像、不把眼睛或脸型拉歪。最大原图位移 12×7 px，对应原生约 1.9×1.1 px；在 80 px 显示下更小，尚未证明全部方向都清楚可辨。

素材：[十六格条](../candidates/phase5/look/strip.webp)、[放大眼部对照](../candidates/phase5/look/eyes-contact.png)、[113 px 亮暗对照](../candidates/phase5/look/contact-113px.png)、[绑定与眼开口边界](../sources/canonical/gaze-rig.json)。隐藏眼白：[局部底图（制作材料）](../candidates/phase5/eye-backing-v1/backing.png)、[生成原始输出（不整张采用）](../candidates/phase5/eye-backing-v1/generated.png)、[内置图像生成实际提示词](../candidates/phase5/eye-backing-v1/prompt.txt)。

第一性原理推导：眼球转向会露出原来被虹膜挡住的眼白；移动整块眼睛、原图加减色或整张重画都不能解决这个遮挡问题。补画只提供缺失眼白，原母版 alpha 覆盖原样保留。由非负、物理有效的预乘材料色层合成，使用同一层的零位移能逐像素还原完整原图 RGBA，不是零位移时直接返回源图的特例。虹膜内部颜色来自原图；边界的透明度仍是估计，不是获得了画师原始层。

为什么精确还原仍不足够：合成式 `S = B*(1-a) + P` 中，即使假定底色 B 已知，每像素也只有三条颜色方程，却有透明度 a 与三通道预乘前景 P 共四个未知量。多组合法分层都能还原同一 S；有些会携带错误眼白，移动后才暴露。这里 B 本身也包含补画估计，因此必须另行检查边界、遮挡和非零视线，不能用中性重建或非负性推导“找到了原始分层”。固定眼外像素、外连眼白与内部高光等约束缩小选择空间，但不消除人工视觉验收。

五步法在这里具体删除了全身方向旋转、独立 AI 新脸和无意义持续重绘；简化为一个母版、两个固定眼开口、一次末端采样。验收区按需解码，只在方向改变时画一格，不宣称原生 FPS、CPU/GPU 或宿主优先级改善。最后才自动化零位移还原、16 格边界外不变、原 alpha 不变、原虹膜内像素平移、合法材料色、两行映射和错误输入拒绝。

否定证据：初版误要求眼内 alpha 必须 255；实际上母版是 252–254，因此构建被拒绝后改为保留原覆盖。首轮估计 matte 带着眼白浅圈移动，隐藏底图还留有旧虹膜细边；精确中性还原并未抓住这些视觉问题。已重新检查取样轮廓、以连通外部眼白区别包围在虹膜内的高光，增加针对凸包内部眼白的回归测试。生成眼白的色值一致性不能作为判定原白色像素是否随虹膜移动的条件。细边仍有估计不确定性，不能写成完美分层、视觉通过或可安装。原始生成在当前眼开口边界外改变 813164 像素，未整张采用；有界组合在眼开口外改变 0。

## 第一性原理与五步工作法的具体作用

1. 质疑要求：角色不是每状态独立插画。真正应守恒的是同一角色的头脸/身体、取景和装饰；手遮挡下颌是合法遮挡，不等于可以重画下颌。宿主的时间槽与三轮回退是事实，不能用更快的演示视频替代。没有“每格必须不同”的要求。
2. 删除错误路线：不整张采用生成输出，不复用旧错误脸/身体，不用淡入淡出伪装手臂中间姿势。关闭普通安装旧 atlas 的隐式入口。
3. 简化实现：一个不可变 v3、一个相机、明确的缺画补片；公用原始高分辨率取样及行输出。口眉、手臂各自有严格边界，不把“共用头部”误当完整身份一致性证明。
4. 优化流程：先查看真实坐标与连接，再做补片；实际尺寸对照复用已经算出的帧，不为每个 CSS 尺寸重复求值；播放器只在真实姿势边界重绘、按需解码候选。没有由此推断原生 CPU/GPU/FPS 改善。
5. 最后自动化：守卫生成源 SHA、补片外逐像素相等、保护眼睛/下颌/衣服、固定整鞋、八姿势坐标场、真实三轮截止与回退、全部保存像素重建一致。自动化只证明这些具体条件。
