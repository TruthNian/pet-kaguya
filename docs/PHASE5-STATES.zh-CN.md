## 新增：十六方向仅眼内视线候选

`look/` 已制作 16 格，0 为上、顺时针每 22.5°，按原生第 9/10 行映射。只平移原虹膜材料；固定眼开口、睫毛、眉、嘴、下颌、身体、月饰及鞋，不全身旋转、不镜像、不把眼睛或脸型拉歪。最大原图位移 12×7 px，对应原生约 1.9×1.1 px；在 80 px 显示下更小，尚未证明全部方向都清楚可辨。

素材：[十六格条](../candidates/phase5/look/strip.webp)、[放大眼部对照](../candidates/phase5/look/eyes-contact.png)、[113 px 亮暗对照](../candidates/phase5/look/contact-113px.png)、[绑定与眼开口边界](../sources/canonical/gaze-rig.json)。隐藏眼白：[局部底图（制作材料）](../candidates/phase5/eye-backing-v1/backing.png)、[生成原始输出（不整张采用）](../candidates/phase5/eye-backing-v1/generated.png)、[内置图像生成实际提示词](../candidates/phase5/eye-backing-v1/prompt.txt)。

第一性原理推导：眼球转向会露出原来被虹膜挡住的眼白；移动整块眼睛、原图加减色或整张重画都不能解决这个遮挡问题。补画只提供缺失眼白，原母版 alpha 覆盖原样保留。由非负、物理有效的预乘材料色层合成，使用同一层的零位移能逐像素还原完整原图 RGBA，不是零位移时直接返回源图的特例。虹膜内部颜色来自原图；边界的透明度仍是估计，不是获得了画师原始层。

为什么精确还原仍不足够：合成式 `S = B*(1-a) + P` 中，即使假定底色 B 已知，每像素也只有三条颜色方程，却有透明度 a 与三通道预乘前景 P 共四个未知量。多组合法分层都能还原同一 S；有些会携带错误眼白，移动后才暴露。这里 B 本身也包含补画估计，因此必须另行检查边界、遮挡和非零视线，不能用中性重建或非负性推导“找到了原始分层”。固定眼外像素、外连眼白与内部高光等约束缩小选择空间，但不消除人工视觉验收。

五步法在这里具体删除了全身方向旋转、独立 AI 新脸和无意义持续重绘；简化为一个母版、两个固定眼开口、一次末端采样。验收区按需解码，只在方向改变时画一格，不宣称原生 FPS、CPU/GPU 或宿主优先级改善。最后才自动化零位移还原、16 格边界外不变、原 alpha 不变、原虹膜内像素平移、合法材料色、两行映射和错误输入拒绝。

否定证据：初版误要求眼内 alpha 必须 255；实际上母版是 252–254，因此构建被拒绝后改为保留原覆盖。首轮估计 matte 带着眼白浅圈移动，隐藏底图还留有旧虹膜细边；精确中性还原并未抓住这些视觉问题。已重新检查取样轮廓、以连通外部眼白区别包围在虹膜内的高光，增加针对凸包内部眼白的回归测试。生成眼白的色值一致性不能作为判定原白色像素是否随虹膜移动的条件。细边仍有估计不确定性，不能写成完美分层、视觉通过或可安装。原始生成在当前眼开口边界外改变 813164 像素，未整张采用；有界组合在眼开口外改变 0。

## 第一性原理与五步工作法的具体作用

1. 质疑要求：角色不是每状态独立插画。真正应守恒的是同一角色的头脸/身体、取景和装饰；手遮挡下颌是合法遮挡，不等于可以重画下颌。宿主的时间槽与三轮回退是事实，不能用更快的演示视频替代。没有“每格必须不同”的要求。
2. 删除错误路线：不整张采用生成输出，不复用旧错误脸/身体，不用淡入淡出伪装手臂中间姿势。关闭普通安装旧 atlas 的隐式入口。
3. 简化实现：一个不可变 v3、一个相机、明确的缺画补片；公用原始高分辨率取样及行输出。口眉、手臂各自有严格边界，不把“共用头部”误当完整身份一致性证明。
4. 优化流程：先查看真实坐标与连接，再做补片；实际尺寸对照复用已经算出的帧，不为每个 CSS 尺寸重复求值；播放器只在真实姿势边界重绘、按需解码候选。没有由此推断原生 CPU/GPU/FPS 改善。
5. 最后自动化：守卫生成源 SHA、补片外逐像素相等、保护眼睛/下颌/衣服、固定整鞋、八姿势坐标场、真实三轮截止与回退、全部保存像素重建一致。自动化只证明这些具体条件。
